# 002 — plan

## Approach

Add `pytest-xdist` and use it where wall time matters: the CI `checks` test step and the
golden workflow. No code under `src/` or test logic changes. Locally plain `uv run pytest`
stays serial; `-n auto` is opt-in and documented.

xdist distributes with `--dist loadgroup`, set once in `addopts` (it is a no-op without
`-n`, checked 2026-10-27). Under `loadgroup` every test is distributed one by one except
tests sharing an `xdist_group` mark, which run on one worker. Six golden modules paint a
whole map once in a module-scoped fixture (setup times from the serial golden run,
2026-10-27): `tests/golden/test_parity.py` (62 s), `tests/unit/maps/test_attribution.py`
(59 s), `test_pipeline_letter_compose.py` (51 s), `lettering/test_notes.py` (48 s),
`test_route_ink.py` (43 s) and `test_pipeline_fetch_paint.py` (43 s). Ungrouped, each
worker that receives one of their tests repaints, up to four times. Each of those modules
gets one `xdist_group` named after the module (`"test_parity"`, `"test_attribution"`, and
so on), applied beside its existing `golden` mark: in `pytestmark` for `test_parity.py`,
on each `@pytest.mark.golden` class otherwise, so every class of a module shares one
group. The other golden modules (`test_docs_images.py`, `test_places.py`,
`test_map_styles.py`, `test_cli.py`, `test_route_map_example.py`) paint per test and stay
ungrouped. Non-golden module fixtures (`painter/test_smoke.py`'s 2 s `job` and smaller)
are left: their repeat cost is seconds.

`--dist loadscope` was rejected: it pins each whole module to one worker, so the 32 docs
image tests (about 14 minutes serial) would run on one worker.

Benchmarks stay serial. pytest-benchmark disables itself under xdist, and CodSpeed's
instrumentation counts one process. The CI benchmark smoke step and `codspeed.yml` keep
their current commands (no `-n`).

The `prerelease` job installs its test plugins by hand (`uv pip install pytest hypothesis
pytest-randomly pytest-benchmark`). With `--dist` in `addopts`, pytest there would reject
the unknown option, so `pytest-xdist` joins that install line. The job stays serial.

No boundary or public-API change, so no ADR. The decision to keep plain runs serial is
recorded in `CONTRIBUTING.md`.

## Test plan

This change adds no test: the existing suites are the check, run under the new commands.

- Fast selection, parallel: `uv run pytest -m "not golden and not benchmark"
  --golden-tolerance -n auto` passes, three times with different `--randomly-seed`
  values (order independence across workers).
- Coverage under xdist: the CI command with `--cov`, then both `coverage report` gates,
  give the same percentages as a serial run to two decimals.
- Golden, parallel, exact locally: `uv run pytest -m golden -n auto` passes (exact mode is
  the local gate). Record wall time and peak resident memory per worker and in total
  (sampled with `ps` every 2 s).
- Each grouped module paints once: `uv run pytest -m golden -n 4 -v` on the six grouped
  modules shows each module's tests on one worker (`-v` prints `[gwN]` per test).
- Plain serial run unchanged: `uv run pytest tests/unit/test_placeholder.py` still runs
  without workers.
- Benchmark smoke: `uv run pytest -m benchmark` passes with no new warning (warnings are
  errors).
- mutmut: `uv run mutmut run "pyntpot.ink.polyline.x_simplify*"` starts its clean run
  and gets past it without an option error; stopping it after the first mutants is enough.
- `prek run --all-files`, `ruff`, `ty`, `lint-imports` green.
- CI: `checks` and both golden runners green; record their times from the PR's runs.

Acceptance criteria map: dependency → `pyproject.toml`/`uv.lock`; serial by default →
plain run; `checks -n auto` + coverage → coverage check; golden both runners → CI;
each module paints once → worker check; benchmarks serial → workflow diff + smoke; memory → the
sampled peak against 7 GB (macOS-15 arm runner) and 16 GB (Ubuntu); times → PR body and
the feature note; docs → `CONTRIBUTING.md`, `CLAUDE.md`; pins exact → no golden file in
the diff.

## Delegation

Small enough to stay in the main context: about 15 changed lines across six files, plus
measurements. The plan-reviewer gate is dispatched (fresh context). The golden runs go to
background shells so the main context reads only their summary lines. A fresh-context
diff review against this plan runs before the PR.

## File-ownership partition

One track, in order: dependency and `addopts` → parity mark → workflows → docs. No
concurrent work, so no worktrees.

## Decisions

- Serial by default locally (rather than `-n auto` in `addopts`): a failing test's
  output stays in order and a debugger works; CI opts in. Picked by the agent; the
  standing criterion is that the local loop reads clearly.
- `loadgroup` over `loadscope`, for the reason above.
- No hard time budget: the maintainer's call (2026-10-27).
- No matrix sharding of the golden job yet: measured parallel time decides whether it is
  worth a follow-up.
